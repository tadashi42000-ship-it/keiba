# APP Functions Manual

## 概要

このアプリは、**直近の重賞レース**を対象にした **競馬情報の収集・整理・可視化アプリ** です。
`Streamlit` で構築されており、サイドバーからレースを選択すると出走馬データ（CSV）を自動取得し、Web記事・YouTube・アップロード資料を解析して、馬ごとの評価（メリット / デメリット）を表示します。

---

## 主な機能（全体）

1. パスワード認証
2. 重賞レース選択（netkeiba.comスケジュールから自動取得）
3. 出馬表自動取得・表示（枠番・馬番・騎手・調教師・オッズ）
4. 最新オッズ取得（netkeiba + Playwright / フォールバックあり）
5. Web一括検索（Tavily優先、Gemini検索フォールバック）
6. GeminiによるWeb記事解析（馬別プラス/マイナス抽出）
7. PDF/TXTアップロード解析（レース特徴 / 馬別情報）
8. 馬別総合予想の集計表示
9. レース特徴・傾向の表示（Geminiで動的生成）
10. YouTube候補検索 + 動画ごとの個別解析

---

## 画面構成（タブ）

### 1. `📋 出馬表`
- 出走予定馬一覧を表形式で表示
- 枠色・オッズバッジ付きの見やすいHTMLテーブル
- `🔄 最新オッズを取得` ボタンで最新オッズ取得
- 取消馬（馬番なし）は表示除外

### 2. `📥 情報入力`
- `🔍 Web 一括検索`
  - Web記事上限数を指定して情報収集
  - Tavily検索を優先
  - 失敗時はGemini検索へ自動フォールバック
- ドキュメントアップロード（PDF / TXT）
  - レース特徴抽出
  - 馬別情報抽出（総合予想に統合）

### 3. `🏇 総合予想（馬別）`
- Web / ドキュメント /（必要に応じてYouTube）由来の情報を馬別に集計
- 各馬ごとにメリット・デメリット・出典を表示
- 情報源数でソート（上位馬が先頭）
- 取消馬は表示除外
- CSVダウンロード対応

### 4. `🏟️ レース特徴・傾向`
- コース特徴（Geminiで動的取得）
- 勝ちやすい馬 / 苦手な馬
- 枠順有利 / 不利
- 過去傾向・注目ポイント

### 5. `YOUTUBEから情報入手`
- YouTube検索（候補一覧表示のみ）
- 各動画ごとに `読み込み+概要取得` ボタンで個別解析
- Geminiで馬別のプラス/マイナスを抽出

## レース選択の仕組み

### データソース
- `race_catalog.py` が netkeiba.com のスケジュールページから重賞一覧を取得
- 当月+2ヶ月分の重賞を日付順で表示

### 選択フロー
1. サイドバーのセレクトボックスでレースを選択
2. `resolve_race_id()` で race_id を遅延解決
3. 出馬表が未公開なら「出馬表未発表」メッセージ表示
4. 公開済みなら `fetch_race_csv()` でCSV自動取得

### レース切替時
- 全レース固有セッションステートをクリア
- キャッシュ(`get_all_horse_names`, `load_race_data`)もクリア
- 旧レースのデータが混入しない設計

### フォールバック
- 重賞一覧取得失敗時: レースIDの手動入力が可能
- サイドバーの展開メニューからも手動入力可能

---

## データソースと役割

### 1. CSV（自動生成）
- ファイル: `data/race_{race_id}.csv`
- 用途:
  - 出走馬一覧のベースデータ
  - 馬名リストの基準
  - 枠番/馬番/騎手/調教師/初期オッズの表示

### 2. netkeiba（Webスクレイピング）
- 用途:
  - 重賞スケジュール取得
  - 最新オッズ、枠番、馬番の取得
- 実装:
  - `Playwright`（優先）
  - 失敗時は別プロセスPlaywright / `requests` フォールバック

### 3. Web記事検索
- Tavily API（優先）
- Gemini Google Search grounding（フォールバック）

### 4. Gemini API
- Web記事スニペットの馬別解析
- YouTube動画説明・字幕の解析
- ドキュメントの馬別情報 / レース特徴抽出
- レース特徴の動的生成

### 5. YouTube Data API
- YouTube動画候補の検索

## Web一括検索の処理フロー

1. 情報入力タブで `Web記事上限数` を指定
2. クエリ群を動的生成（レース名ベース + 馬名グループクエリ）
3. 各クエリごとに検索実行
   - まず Tavily
   - 失敗 / 未設定 / 空結果なら Gemini検索
4. 記事メタデータを収集（記事上限数まで）
5. 各クエリの代表記事（先頭1件）をGemini解析
6. 馬別のプラス/マイナス情報を抽出
7. `aggregate_horse_analysis()` で馬別集計
8. 取消馬を除外して総合予想に反映

## 主要な内部データ（Session State）

- `selected_race`
  - 選択中のRaceInfoオブジェクト
- `horse_df`
  - 総合予想（馬別）の表示用DataFrame
- `web_articles`
  - 取得したWeb記事メタデータ一覧
- `web_raw`
  - Gemini解析後の生データ（馬名 / プラス / マイナス / 出典）
- `doc_horse_raw`
  - アップロード資料から抽出した馬別情報
- `race_characteristics`
  - レース特徴タブの表示データ（Geminiで動的生成）
- `latest_odds`
  - 出馬表に反映する最新オッズ
- `latest_odds_error`
  - オッズ取得失敗時の詳細ログ（表示用）

## 外部API / Secrets 設定

### 必須（運用内容による）
- `PASSWORD`
- `GEMINI_API_KEY`

### 任意（機能に応じて）

```toml
TAVILY_API_KEY = "..."
```

## エラーハンドリングの特徴

### レース選択
- 重賞一覧取得失敗 → 手動入力フォールバック
- race_id 未解決 → 「出馬表未発表」表示
- CSV取得失敗 → エラーメッセージ表示

### レース特徴
- Gemini失敗時 → `get_minimal_race_characteristics()` でRaceInfoから最小限の特徴を表示

### オッズ取得
- 失敗時に詳細メッセージをUIへ表示
- 一時的な通信/描画失敗を考慮してリトライあり

### Web検索
- Tavilyが失敗してもGemini検索へフォールバック
- APIキー未設定時も処理中断ではなくフォールバック可能（Geminiが有効なら継続）

### 解析結果の揺れ
- Geminiの返却値が `str` 以外（`list`, `dict`, `None`）でも落ちないように正規化

## 取消馬の扱い（重要）

現在は以下のルールで取消馬を非表示にしています。

- `馬番` が1頭でも確定している場合
  - `馬番` 欠損行は「取消/非出走」とみなし除外
- `馬番` が全頭未確定の場合
  - 除外しない（出走確定前とみなす）

反映箇所:
- 出馬表タブ
- 総合予想（馬別）タブ

## 既知の運用注意点

1. Streamlit Cloud では `.env` は使われない
- Cloudでは `Secrets` に設定が必要

2. 無料枠アプリはスリープする
- 一定時間アクセスがないとスリープ
- 再起動時にキャッシュが消える

3. Tavily / Gemini のAPI利用量管理が必要
- Web記事上限数を上げるほど時間/コスト増

4. スクレイピング先のHTML変更に弱い
- netkeibaのHTML変更時はオッズ取得/スケジュール取得ロジック修正が必要
